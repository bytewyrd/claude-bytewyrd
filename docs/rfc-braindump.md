# RFC Braindump

Potential RFC ideas. Add with `/rfc-braindump`, promote to full RFC with `/rfc-new`.

* **project-brief as the Single Source of Truth in /sync.** The `/sync` skill currently asks for project name and description separately, even though `docs/project-brief.md` already captures this information (and more). Instead, `/sync` should treat the project-brief as the canonical source of project identity: on first run, generate a project-brief interactively (name, description, goals, audience, key constraints), and on subsequent runs skip that step entirely since the brief already exists. All other artifacts that /sync produces (CLAUDE.md headers, README snippets, etc.) should read from the brief rather than re-prompting. This eliminates duplicate data entry, keeps project identity consistent across files, and makes the brief the single place to update when the project evolves.
* **Best-practice extraction must distinguish generalizable principles from project-specific facts, and abstract upward before recording.** Knowledge-capture systems that operate at the literal level of the source material accumulate two failure modes: project-specific gotchas leak into shared/global stores where they don't belong, and genuinely transferable insights get frozen at the narrow scope they were first observed in, losing reusability. The fix is a triage-and-lift step at capture time — first decide whether a learning is generalizable at all (route project-specific facts to project-local docs instead), then for generalizable items, restate them at the level of the underlying principle rather than the originating instance ("subsystem boundaries own their domain assembly; configuration layers only resolve and forward inputs" rather than "K8s auth belongs in core::k8s::target"). This turns a knowledge store into something that compounds across projects rather than a graveyard of one-off observations.
* **/refactor command for explicit refactoring subagent.** Add a `/refactor` slash command that spawns a dedicated refactoring subagent with Opus + max thinking. The main agent proposes an initial scope (recent PR code, code about to be touched by an RFC implementation, etc.) and can pre-emptively invoke `/refactor` when it would be beneficial — for example, to expand test coverage on areas about to change, or to improve architecture ahead of a new feature. The intent is to make refactoring a first-class, deliberately-invoked step rather than something that gets tacked onto feature work, while keeping the heavyweight model reserved for genuine refactor passes.
* **claude-plugin-author agent for scaffolding and maintaining Claude Code plugins.** A specialized agent with deep knowledge of the Claude Code plugin format — `plugin.json` manifest, skill frontmatter fields (`model:`, `effort:`, `context:`, `disable-model-invocation:`), agent definition conventions, hook structure, and the promote-through-production workflow. Useful when creating a new skill from scratch, debugging why a skill isn't resolving, adding a new agent, or wiring up hooks — tasks where the main agent currently has to rediscover plugin conventions from the codebase each time.
* **Claude agent author agent.** Add a `claude-agent-author` specialist agent with deep, researched knowledge of Claude Code's subagent format, frontmatter conventions, tool selection patterns, model-tier choices, and prompt structure. Solves the gap left after vendoring agents from VoltAgent/awesome-claude-code-subagents — the project now owns those files but lacks an in-house authority for creating new agents or refactoring existing ones consistently. Approach hint: drive the agent's system prompt from primary-source research (Anthropic docs, Claude Code release notes, observed conventions in the current `agents/` directory) rather than training-knowledge defaults, so it stays current with format changes.
* **Audit and rework all agent definitions with claude-agent-author.** Run the proposed `claude-agent-author` agent across every file in `agents/` (originally vendored from VoltAgent/awesome-claude-code-subagents, now locally owned) to systematically audit and improve each definition. Each change must come with explicit, documented rationale explaining why the improvement makes sense — keeping the rework reviewable rather than opaque. Depends on `claude-agent-author` existing first; output should preserve agent intent while raising quality consistently across the set.
